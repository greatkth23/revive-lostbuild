## 0. 핵심 결론

현재 계산기는 API·엑셀·사용자 확정 규칙·예시 계산 데이터가 혼합된 프로토타입이다.

특히 다음 세 가지를 먼저 바로잡아야 한다.

1. 활성 아크그리드 젬의 보스 피해 합계 `+3.62%`가 API 원문에 있지만 파서 문구 불일치로 `0%` 처리됐다.
2. `타격의 대가 +17%`는 현재 API 설명에 수치가 있는데도 파서가 문장을 인식하지 못해 예시 DB fallback을 쓴다.
3. 모든 아크 패시브 소스에 기록된 `applied=true`는 “파싱 성공”이라는 뜻에 가깝고 실제 피해 계산 반영 여부를 정확히 나타내지 않는다.

따라서 현재 결과의 `validation.passed=true`는 내부 산술·중복 적용 검사 통과를 의미할 뿐, 모든 게임 효과를 완전하게 반영했다는 뜻이 아니다.

### 1.3 의도하지 않은 파싱 누락

활성 아크그리드 젬 원문에는 아래 보스 피해가 존재한다.

```text
0.41 +0.33 +0.33 +0.25 +0.16 +0.41
+0.25 +0.33 +0.41 +0.41 +0.33
= +3.62%
```

현재 정규식은 `보스에게 주는 피해` 또는 `보스 피해`만 인식한다. 실제 문구인 `보스 등급 이상 몬스터에게 주는 피해`는 인식하지 못하므로:

```text
arkGrid.bossDamagePercent = 0
```

이 되었다. 반면 같은 젬의 공격력 `+1.32%`, 추가 피해 `+3.92%`는 정상 반영됐다.

이 결함 때문에 현재 보고된 결과는 활성 젬 보스 피해 `+3.62%`가 빠진 값이다. 다른 모든 값이 동일하다는 단순 가정으로 이 배율만 추가하면 참고값은 다음과 같다.

| 결과 | 현재 파일 | 보스 젬 3.62%만 추가한 참고값 |
|---|---:|---:|
| 비치명타 | 435,266,285 | 451,022,925 |
| 치명타 | 1,284,528,613 | 1,331,028,548 |
| 기대 피해 | 1,248,519,890 | 1,293,716,310 |

이 참고값은 파서를 수정하고 전체 검증을 다시 수행한 정식 결과가 아니다.

### 1.4 출처·적용 상태 표기의 문제

- `arkPassive.sources[].applied=true`는 실제로는 “API에서 노드를 읽음”을 뜻한다.
- 환기, 공간 가르기, 잠재력 해방처럼 최종 식에서 사용되지 않는 노드도 `applied=true`다.
- `회심 +12%`는 현재 API 아크 패시브 설명에서 직접 파싱됐지만 계산 가정에는 `API_TOOLTIP+EXAMPLE_DB`로 기록된다.

향후에는 다음 상태를 분리해야 한다.

```text
parsed: 원문을 정상적으로 해석했는가
eligible: 현재 스킬·대상·시나리오에 적용 가능한가
applied: 실제 계산식에 한 번 반영됐는가
excluded_reason: 제외 이유
```

### 2.4 엑셀에서 가져온 것은 “구조”이지 완전한 효과 DB가 아니다

엑셀에서 확보한 핵심은 다음과 같다.

- 주스탯·무기 공격력·공격력 파이프라인
- 평면 증가와 퍼센트 증가의 위치
- 추가 피해 내부 합산
- 소제목 간 곱연산
- 기대 피해 구조
- 엑셀 버전의 중간 버림 위치

그러나 엑셀이 다음을 완전히 제공하지는 않는다.

- 모든 스킬의 계수·상수·타격 구조
- 모든 효과의 패치별 수치표
- 효과별 대상 스킬과 조건
- 카르마 전 구간 표
- 보스 DB
- API 툴팁 문구 변형 사전

### 3.2 API 공식 + 계산 규칙으로 파생

#### 기민함 Lv.3

API 설명:

```text
기본 공격 속도 증가량의 120%만큼 치명타 피해 증가
기본 이동 속도 증가량의 30%만큼 치명타 적중률 증가
```

현재 최대 유리 규칙:

```text
치명타 피해 = 40% × 120% = 48%
치명타율     = 40% × 30%  = 12%
```

#### 음속 돌파 Lv.2

속도 입력:

```text
공격속도 = 1 + 신속 28.24% - 질량 증가 10%
          + 전투 축복 9% + 만찬 5% + 질풍노도 12%
          = 1.4424

이동속도 = 1 + 신속 28.24%
          + 전투 축복 9% + 만찬 5% + 질풍노도 12%
          = 1.5424
```

음속 돌파:

```text
기본분 = 10% × [min(44.24%, 40%) + min(54.24%, 40%)]
       = 8.0000%

양쪽 상한 초과 = 8.0000%

초과분 = 30% × [(44.24%-40%) + (54.24%-40%)]
       = 5.5440%

합계 = 21.5440%  (< 최대 24%)
```

### 3.3 예시 DB fallback

| 효과 | API 상태 | 적용값 |
|---|---|---:|
| 깨달음 카르마 | `6랭크 27레벨`만 제공 | 무기 공격력 `+2.7%` |
| 진화 카르마 | `6랭크 21레벨`만 제공 | 진화형 피해 `+6.0%` |

### 3.4 중복 적용 방지

진화 1티어의 치명 `+700`, 신속 `+1,300`은 프로필의 최종 치명·신속 및 해당 툴팁 환산값에 포함된 것으로 처리한다. 따라서 아크 패시브 효과에서 다시 더하지 않는다.

## 4. DB 체계화 계획

### 4.1 권장 아키텍처

```text
1. immutable API snapshot
2. normalized observations
3. versioned knowledge DB
4. scenario preset
5. calculation run + provenance ledger
```

API 원문, 파싱 결과, 게임 규칙, 사용자 시나리오를 한 객체에 섞지 않는다.

초기 저장소는 SQLite가 적절하다. 사용자가 편집할 자료는 CSV/XLSX 템플릿으로 받고, 검증 후 SQLite로 import한다. 규모가 커지면 동일 스키마를 PostgreSQL로 옮긴다.

### 4.3 출처 등급

혼합형 `API_FIELD+EXAMPLE_DB` 문자열을 없애고 관측과 규칙을 별도 레코드로 연결한다.

권장 등급:

```text

USER_VERIFIED
WORKBOOK_FORMULA
EXPERIMENTAL_MEASUREMENT
COMMUNITY_REFERENCE
LEGACY_EXAMPLE
DERIVED
```

검증 상태:

```text
VERIFIED
PROVISIONAL
DEPRECATED
REJECTED
```

### 4.4 계산 모드

```text
STRICT_VERIFIED
```

- 검증된 DB가 없는 효과는 계산을 중단하거나 명시적으로 제외한다.
- 예시 fallback을 절대 자동 적용하지 않는다.

```text
ESTIMATE_WITH_FALLBACK
```

- fallback을 허용하되 결과에 영향도와 경고를 표시한다.
- fallback 사용 전후 결과를 함께 출력한다.

운영 기본값은 `STRICT_VERIFIED`, 연구·프로토타입용은 `ESTIMATE_WITH_FALLBACK`이 적절하다.

### 4.5 버전 정책

세 버전을 독립적으로 기록한다.

```text
parser_version: API 문구를 어떻게 읽는가
ruleset_version: 계산 순서·그룹·반올림 규칙
db_release: 효과·스킬·보스 데이터 내용
```

결과에는 반드시 다음 식별자를 남긴다.

```text
api_snapshot_id
parser_version
ruleset_version
db_release
scenario_preset_id
calculation_engine_commit
```

## 5. 우선순위

### P0: 현재 결과 신뢰성

1. 아크그리드 젬의 `보스 등급 이상 몬스터에게 주는 피해` 파싱 수정
2. `타격의 대가` API 문구 직접 파싱
3. `parsed / eligible / applied` 상태 분리
4. 모든 fallback을 결과 파일의 구조화 목록으로 노출
5. 현재 봄날꽃씨 API 스냅샷으로 파서 회귀 테스트 추가

### P1: 예시 DB 제거

1. 카르마 랭크·레벨 전체 표
2. 어빌리티 스톤 기본 공격력 표
3. 아바타 등급·부위 효과표
4. 레벨·원정대·내실 주스탯 표 또는 사용자 실제값 입력
5. 펫·도감·만찬·외부 버프를 시나리오 DB로 이동

### P2: 스킬·효과 범위

1. 스킬 태그 DB로 타격의 대가·바람의 길·풀려난 힘 적용 검증
2. 일반 보석 스킬 피해·쿨감 파싱
3. 추가 타격·스킬 변형·타격별 계수 모델
4. 1회 피해와 로테이션 DPS 엔진 분리

### P3: 운영

1. 패치별 DB release
2. API 문구 스냅샷 diff
3. 미등록 효과 자동 격리
4. 검증 대시보드와 영향도 비교

## 6. 사용자가 준비할 자료

### 6.1 가장 먼저 필요한 필수 자료

1. **스킬 계수표**
   - 우레바람을 포함한 스킬별 계수·상수·타격 구조
   - 아크 패시브/아크그리드로 동작이 변경될 때의 변형 계수
   - 확인 패치와 근거

2. **효과 적용 규칙표**
   - 효과명·레벨별 수치
   - 합연산 그룹 또는 독립 곱연산 여부
   - 적용 스킬 태그
   - 최대 스택·조건
   - 추가 타격에 적용되는지

3. **카르마 전체 표**
   - 진화·깨달음·도약
   - 랭크와 레벨별 실제 수치
   - 패치 버전

4. **어빌리티 스톤 보너스 표**
   - 돌 레벨 조합/합계와 기본 공격력 증가의 정확한 대응

5. **아바타·펫·내실 표**
   - 아바타 부위·등급별 주스탯
   - 펫 특기 실제 옵션
   - 카드 도감/물약/원정대 주스탯과 종족 피해

6. **보스 표**
   - 방어력, 받는 피해 배율, 종족, 관문·페이즈, 패치

7. **검증 사례**
   - API 원본 스냅샷
   - 적용 효과 목록
   - 중간 공격력·배율
   - 치명·비치명 결과
   - 패치 날짜

### 6.3 사용자에게 필요한 판단

다음 정책은 데이터만으로 결정되지 않으므로 사용자가 확정해야 한다.

- 기본 출력이 실제 캐릭터 상태인지, 최대 유리 상태인지
- 확률 효과를 발동 피해와 기대 피해 중 무엇으로 표시할지
- 외부 버프 기본 프리셋
- 보스 미선택 시 기본 대상
- 미등록 효과 발견 시 중단할지 0으로 제외할지
- 추정값이 하나라도 포함되면 결과를 “검증됨”으로 표시할 수 있는지

## 7. 권장 다음 작업

첫 DB 릴리스는 모든 클래스를 대상으로 하지 않고 다음 범위로 제한한다.

```text
DB release: weather-artist-v0.1
클래스: 기상술사
스킬: 우레바람, 칼바람, 공간 가르기
효과: 현재 API 스냅샷에 등장한 각인·아크 패시브·아크그리드 젬
대상: 예시 보스 1종
모드: STRICT_VERIFIED / ESTIMATE_WITH_FALLBACK
```

이 범위에서 provenance와 검증 구조를 완성한 뒤 다른 클래스에 확장하는 것이 안전하다.
